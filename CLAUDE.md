# Проект 3: REST API с авторизацией и документацией

## Цель
Портфолио-проект для Kwork, показывающий чистый бэкенд: бэкенд для мобильного приложения или интернет-магазина. Главное здесь качество кода, тесты и документация.

## Стек
- Laravel (последняя стабильная версия), PHP 8.2+
- Laravel Sanctum (токены), роли и права
- Документация: Scribe или Swagger (L5-Swagger)
- Redis для кэша и очередей
- Pest или PHPUnit для тестов
- Docker (docker-compose) для удобного запуска

## Предметная область
Выбрать на старте одну из двух и держаться её:
- Бэкенд магазина: товары, категории, корзина, заказы
- Бэкенд приложения задач или заметок с командами и правами

## MVP (версия 1)
1. Регистрация, вход, выход, обновление профиля (Sanctum)
2. Основные ресурсы с CRUD, пагинацией, фильтрами и сортировкой
3. API Resources для единообразных ответов и единый формат ошибок
4. Form Requests для валидации, Policies для прав
5. Автогенерируемая документация с примерами запросов
6. Feature-тесты на все основные эндпоинты

## Развитие (по этапам)
- Этап 2: очереди и фоновые задачи (email, экспорт)
- Этап 3: кэширование через Redis, rate limiting
- Этап 4: версионирование API (v1, v2)
- Этап 5: CI (GitHub Actions) с прогоном тестов и линтером, деплой через Docker

## Требования для портфолио
- Публичная документация API (ссылка в README и кворке)
- Postman-коллекция или OpenAPI-файл
- Покрытие тестами основных сценариев
- README с описанием архитектуры и запуском одной командой

## Инструкции для Claude Code
- Придерживаться PSR-12 и принципов тонких контроллеров (логика в сервисах и действиях)
- Каждый эндпоинт сопровождать тестом и описанием в документации
- Перед стартом предложить структуру БД и список эндпоинтов
